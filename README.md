# Design Loop 准备包

本目录是新版 Design Loop 的源包，日常执行时作为只读流程与设计资源使用。总入口见 [`00_总流程/Design Loop总流程与调用时机.md`](00_总流程/Design%20Loop总流程与调用时机.md)；真实 Case 写入桌面独立工作区。

## 安装

**先看 [`环境要求.md`](环境要求.md)** —— 里面列清了哪些必须你本人准备（Figma 账号与连接、Product Design 插件、Python ≥3.10、Mobbin 订阅），哪些 AI 会自己搞定。

然后将本文件夹作为工作区打开，输入：

> 请安装这个 Design Loop 包。

AI 将自动安装包内 Skill，自动发现、安装、配置并连接 Product Design、Figma、Mobbin 和 Agent Reach，并逐项告诉你还缺什么。只有登录、OAuth 同意、系统级安装或权限批准等必须由本人完成的动作，才会请你操作。

开始需求时**必须同时给一个节点级 Figma 链接**（带 `node-id=`）：改造现有产品给目标页面，全新项目给设计系统页或参考页。后续所有出图都以它为视觉基线。

## 使用规则

1. 每个新 Case 由 AI 自动复制 `04_Case归档模板` 到桌面 `Design Loop Cases/<Case名称>/`；源模板留在包内且不写入真实 Case 内容。
2. 每一步进入下一步前，AI 必须按本步输出标准自检；未达到就在本步继续循环。
3. 上一步已确认的产出作为下一步输入，不重复传递完整对话。
4. 每一步必须完整执行总流程中列出的 Skill 调用；任何设计出图都必须先成功调用 Product Design 的具体工作流。
5. 每一步开始和结束都只给一句明确引导；研究、发散和 QA 过程由 AI 内化，用户只接收本步规定的精简交付。
6. Step 2 不归档竞品图片，只交付一个基于节点级 Figma 原稿、高还原且链路完整的多方案 HTML 画板。
7. 所有真实 Case 的过程文件和交付物只写入桌面 Case 目录；Design Loop 包在日常执行中作为只读流程与设计资源使用。
