# 视觉设计执行规范

> **本文件是通用设计知识的兜底层。** Shopee 设计系统（L1–L5）规定了这个项目怎么做；本文件规定 Shopee 没规定的地方按什么通用原则做。
>
> 两者关系：**Shopee 有定义 → 用 Shopee；Shopee 留白 → 用本文件；本文件也没有 → 才由 AI 依据通用设计判断，并在交付时说明依据。**
>
> 内容来源：原 `frontend-design` 与 `ui-ux-pro-max` 中与设计系统不冲突的通用部分。`ui-ux-pro-max` 已于 2026-08-09 移出流程，其唯一有价值的图表选型知识收编为 [`图表选型.md`](图表选型.md)。`frontend-design` 保留，只在 Step 1 文案基线阶段强制使用。

## 一、使用顺序

设计前按以下优先级读取与执行：

1. 当前需求和已锁定的视觉预期
2. 产品现有页面、品牌规范和设计系统
3. 组件库与 Token
4. 本通用规范

本规范不覆盖已有产品规范。已有组件、颜色、字体、间距或交互规则时，必须优先复用；只有现有规范未定义的部分，才允许依据本规范补充判断。

视觉预期的对齐方式见 [`视觉预期卡.md`](视觉预期卡.md)。

## 二、出稿前先定视觉策略

开始画稿前，先在内部明确以下内容：

- **页面任务**：这次设计主要帮助用户完成什么。
- **视觉焦点**：用户第一眼、第二眼、第三眼分别看到什么。
- **视觉角色**：新增内容看起来像提醒、工具、推荐、状态还是其他角色。
- **延续关系**：哪些地方必须继承现有产品，哪些地方允许有新表达。
- **记忆点**：若需求允许，只选择一个值得被记住的视觉特征，其余部分保持克制。

不得在未理解业务内容时先套风格。视觉选择必须能解释它为什么适合当前产品、用户和场景。

## 三、视觉层级

- 每个页面或局部区域只能有一个第一视觉焦点。
- 视觉强弱必须对应信息优先级，不能让装饰比任务更抢眼。
- 使用大小、位置、对比、留白、字重建立层级，不依赖单一手段。
- 标题只在需要建立信息类别、上下文或扫读入口时使用；正文可独立表达且标题会抢注意力时，可不设标题。
- 结构元素必须表达真实关系。编号只用于真实顺序，分割线只用于真实分组，标签只用于真实状态或分类。
- 同层级内容使用一致的视觉权重；不同层级必须能被快速区分。

## 四、布局与信息密度

- 先搭页面骨架，再放组件和内容。
- 使用统一网格、对齐线和间距 Token，不使用随意数值修补布局。
- 信息密度由使用场景决定。工作台、管理后台可以紧凑，但必须保持清晰分组和稳定扫读路径。
- 留白用于表达关系，而不是单纯制造“高级感”。相关内容靠近，不相关内容拉开。
- 内容变化后布局仍需成立：长文案、更多标签、空内容、错误状态不能导致错位或溢出。
- 只在卡片确实表达独立对象或独立任务时使用卡片，避免把每块内容都装进容器。
- **异步内容要预留空间**，用固定高度或宽高比占位，不让图片和延迟加载的内容把已渲染的布局挤走。

## 四之二、图表

图表选型、数据量阈值和无障碍兜底见 [`图表选型.md`](图表选型.md)。核心一条：数据点少于 4 个用 MetricsCard，用户要读精确值用 Table，图表只回答趋势和比例。

## 五、颜色

- 颜色优先使用现有品牌与语义 Token，不创建近似色或无来源的新色值。
- 主色用于主操作和品牌强调；成功、警告、错误、信息色只表达对应语义。
- 同一区域避免出现多个高饱和焦点。
- 不只依赖颜色传达状态，必须同时提供文字、图标或形状提示。
- 正文与背景对比度目标为 WCAG AA：普通文本 `4.5:1`，大文本 `3:1`。
- **项目色板不满足该目标时，以项目色板为准，按用途分层处理，不得为凑对比度自造色值。** Shopee 项目的分层规则与实测比值见 [`../../Shopee设计系统/L1_原子变量/README.md`](../../Shopee设计系统/L1_原子变量/README.md) 的「文本对比度」一节——其中 Success 与 Warning 的文本变体确实达不到 4.5:1，处理方式是配图标或状态文案，而不是改色。
- 渐变、发光、透明玻璃等效果只能在符合产品气质且有明确作用时使用，不能作为默认美化手段。

## 六、字体与文案

- 使用稳定的字号层级，不临时增加相近字号。
- 字号、字重、行高和字距共同表达层级；避免只靠加粗解决所有重点。
- 展示字体、正文字体和数据字体如有多个角色，必须分工明确，并与现有品牌兼容。
- 文案是设计材料。每段文字只承担一个任务：标题负责建立语境，正文负责说明，按钮负责动作。标签就是标签，示例就是示例，不让任何元素悄悄兼职。
- **从用户这一侧命名，不按系统实现命名。** 用户管理的是「通知」，不是「webhook 配置」；是「商品」，不是「SKU 记录」。
- 使用用户能理解的业务词和主动语态。按钮直接写点击后的结果，例如 `Save changes`，不写模糊的 `Submit`。
- 同一动作在按钮、过程状态和结果反馈中保持同一名称：按钮写 `Publish`，成功提示就写 `Published`。
- **描述功能做什么，不推销它。** 具体永远优于机灵。
- 错误信息说明发生了什么以及如何解决；**用界面的口吻，不道歉、不含糊**。空状态给出下一步，不写无意义情绪文案。
- 句式用 sentence case，不加填充词，语气与受众匹配。

## 七、组件与图标

- 优先复用已有组件及其正确变体，不为视觉新鲜感重画基础组件。
- 同类组件的圆角、边框、阴影、内边距和状态保持一致。
- 一组操作最多一个主按钮；其他操作主动降级。
- 图标使用同一图标库，不混用不同线宽、透视和填充风格。
- 图标用于识别、状态或操作，不用于填空；不使用 Emoji 代替界面图标。
- 只有图标的按钮必须有可访问名称，并提供 Tooltip 或其他必要说明。

## 八、交互与动效

- 所有可点击元素都要有清晰的默认、悬停、按下、聚焦、禁用状态。
- 键盘焦点必须可见，Tab 顺序应与视觉顺序一致。
- 动效只用于解释状态变化、空间关系或操作反馈。
- 优先设计一个有意义的关键动效，避免多个零散动画同时争抢注意力。
- 常规状态过渡保持短促克制；复杂动效按场景判断。**Shopee 项目不适用此处的通用建议**——它有自己的动效规范（最快 100ms / 基本 200ms / 较大 400ms，以 100 倍增，配三条指定缓动曲线），见 [`../../Shopee设计系统/L3_全局规范/全局规范.md`](../../Shopee设计系统/L3_全局规范/全局规范.md) §八之二。项目无自有动效规范时，通用参考值为 `150–300ms`。
- 尊重 `prefers-reduced-motion`，减少非必要位移和循环动画。

## 九、避免模板化与 AI 感

出现以下情况时必须重新检查设计是否真的来自当前需求：

- 不加判断地使用大渐变、玻璃拟态、发光、超大圆角或悬浮卡片。
- 每个区块都使用相同卡片结构，页面缺少真实的信息关系。
- 使用无业务含义的 `01 / 02 / 03`、装饰标签或随机几何图形。
- 使用一套可以无差别替换到任何产品上的配色、字体和插画。
- 为了“更丰富”加入多个图标、色块和动效，导致视觉焦点分散。
- 文案像营销模板，只有形容词，没有具体功能或结果。

视觉个性应来自产品本身的内容、工具、行为和品牌语言，而不是流行效果的叠加。

## 十、两轮出稿法

### 第一轮：方向

先确定：

- 信息层级
- 布局与密度
- 字体角色
- 颜色角色
- 唯一视觉记忆点（如需求允许）

检查这个方向是否符合视觉预期、现有产品和真实内容。任何可以原封不动移植到其他产品的选择，都要重新判断。

### 第二轮：完成度

在方向成立后处理：

- 对齐与间距
- 文案长度与截断
- 组件状态
- 悬停与聚焦反馈
- 对比度与键盘可达性
- 目标尺寸下的布局稳定性

完成后使用截图检查整体视觉，不只在代码或局部组件中判断。

## 十一、交付前自查

- [ ] 第一视觉焦点与需求优先级一致
- [ ] 新增模块符合已确认的视觉角色
- [ ] 页面骨架、组件和 Token 沿用现有系统
- [ ] 没有多个同等强度的主操作或高饱和焦点
- [ ] 标题、正文、按钮各自只承担一个任务
- [ ] 布局在长文案、空态、加载态和错误态下仍成立
- [ ] 颜色没有被单独用于传达状态
- [ ] 正文、标题、表格数据只用 `colorTextHeading` / `colorText` / `colorTextSecondary`
- [ ] 彩色文字用 `*Text` 变体而非主体色（`colorPrimaryText` 而非 `colorPrimary`）
- [ ] Success / Warning 未仅靠彩色文字承载信息，已配图标或状态文案
- [ ] 灰底区域内的链接与错误文字已改用 `colorInfoText` / 已确认比值达标
- [ ] 所有可点击元素有悬停、按下和可见焦点状态
- [ ] 图标来自同一图标库，图标按钮有可访问名称
- [ ] 动效有明确作用并支持 reduced motion
- [ ] 已删除无业务意义的装饰与模板化效果
- [ ] 已用截图进行整体复核

## 十二、判断边界

- 本规范负责视觉质量和通用可用性，不替代产品目标、功能逻辑和业务规则。
- 视觉预期由 PM 与设计共同确认；具体视觉方案由设计提出。
- 如果项目规范与本文件冲突，以项目规范为准，并记录冲突，不擅自重建设计系统。
