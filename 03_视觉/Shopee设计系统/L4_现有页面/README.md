# L4 现有页面

L4 保存真实页面拆解，用于对齐已有产品的结构、交互和视觉关系。

**出稿起手顺序：有整页模板 → 从模板起手；无模板但有拆解 → 按拆解配方；两者都无 → 回 L3 页面骨架配方。**

## 调用时机

只有本次需求存在相同或相近页面类型时读取。没有对应页面时从 L3 页面骨架开始。

### ⚠️ 模板中的"复制块"

多个整页模板的描述明确注明：部分区块是**从原设计直接复制、instance 已 detach、只重新绑定了 Token**（例如 My Product 的 banner 与商品表格、My Orders 的订单卡片模块、Homepage 的各 Home/\* 卡片）。

对这类区块：

- **不是 library 组件**，不随 library 更新。
- **不能当作组件契约的依据**——它的变体属性、间距、层级都不代表规范。
- 可以参考它的信息结构和业务字段，但重做时应优先用已建组件重新拼装。
- 拆解时必须逐块标注「库组件」还是「复制块」。

## 二、拆解格式

新增拆解按 [`_拆解模板.md`](_拆解模板.md) 写，文件名 `{页面标识}.teardown.md`。核心要求：

1. 骨架树（AppShell 层级）
2. 逐区块表：区块 → **组件 + 确切变体** → componentKey → 状态（✅ 直接可用 / 🔧 需扩展 / 🔴 需新建 / 📋 复制块）
3. 复合区块的组合方式
4. 建造清单（真实缺口，区分"改配方"和"建组件"）
5. 参考边界（可参考 / 不可照抄）

颗粒度必须到「区块 → 组件 + 哪个变体」，停在「列表页 = Header + Filter + Table」的粒度不算完成。

## 三、参考边界

### 可以参考

- AppShell、Header、Sidebar 和内容区的层级关系
- 同类任务的页面骨架
- 已确认的组件与变体组合
- 已有操作的交互方式和状态表达
- 信息密度、对齐关系和内容组织

### 不可直接照抄

- 未经需求确认的字段、顺序和业务文案
- 历史遗留问题或临时实现
- 与 L1–L3 明确规则冲突的做法
- 只适用于原页面数据规模、权限或场景的细节
- 页面截图中的裸数值和视觉近似值
- **模板中标注为「复制块」的区块的实现方式**

## 四、冲突处理

1. 当前需求和已确认交互方案优先。
2. L1–L3 的明确规范优先于 L4 实例。
3. L4 与当前 Figma 不一致时，以当前 Figma 为准。
4. 无法判断是否为历史问题时，标记为待确认，不直接沿用。

## 五、待补页面

- **详情页** —— 同上。
