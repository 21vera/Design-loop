# Shopee 规范

本目录是 Shopee 视觉输出的项目规范和组件索引，只在 Step 3B、Step 4 使用。

## 读取顺序

1. 先读 `L4_现有页面`：有整页模板就从模板起手，有拆解就按拆解配方，两者都无再回 L3 配方。同时明确可参考和不可照抄的部分。
2. 读 `L3_全局规范/全局规范.md`，确定页面骨架和跨组件规则。涉及数字/金额/日期时加读 `数字与日期规范.md`；涉及表单、表格、弹层或批量操作时加读 `键鼠交互规范.md`。
3. 读 `L2_组件/组件索引.md`，选择组件。
4. 只读取本次使用组件的 `.usage.md`。
5. 读 `L1_原子变量`，从 Figma 取得 Token。
6. 交付前执行 `L5_检查项`。

不要从 L1 或组件列表直接开始拼页面。

## 五层职责

| 层 | 职责 | 当前状态 |
|---|---|---|
| L1 原子变量 | 三层 Token 架构、完整 token 表和 Figma 真源 | 已于 2026-08-09 从 Design Token 页全量抄录 |
| L2 组件 | 组件索引、用法、变体和反例 | 索引已于 2026-08-09 与 library 全量对账；多数组件 usage 文档待补 |
| L3 全局规范 | 页面骨架和跨组件规则 | 可用 |
| L4 现有页面 | 整页模板登记、真实页面拆解与参考边界 | 5 个整页模板已登记，其中 My Products 已拆解，其余 4 个待拆解；表单页 / 详情页 / 弹层任务无模板也无拆解 |
| L5 检查项 | 从 L1–L4 派生的客观检查 | 可用；含「未建组件降级规则」 |

## 边界

- Figma 是组件变体和 Token 的真源；文档冲突时以当前 Figma 为准并记录差异。
- L4 是实例，不是规范真源；历史做法不得覆盖 L1–L3 的明确规则。
- `_建设参考`（组件建设资料）已于 2026-08-10 移出 Design Loop 包，归档在包外 `Design-loop-归档/_建设参考/`；只在新增或维护组件时读取，日常出稿不读取。
- 找不到组件时先确认是否可组合现有组件，再提出新增组件；不得直接自画伪组件。

## 已知缺口

- L1 已补齐 Base / Alias / Foundation 三层的完整数值；Tier 3 组件级 Token 只记录了命名规则，具体 token 仍需按组件现读 Figma。
- Neutral Alias 页面标注 35 个 token、实读 31 个，差额待复核。
- 多数组件文档仍含旧代码属性，变体选择应以 Figma 为准。
- L2 索引中 6 个历史 node-id 已失效，引用组件一律用 `componentKey`。
- L4 已登记 5 个整页模板，但只有 My Products 完成拆解；My Orders / Homepage / Marketing Centre / Ads Page 待拆解（需要节点级链接）。
- L4 缺表单页、详情页和弹层任务——library 中也没有对应整页模板，这三类目前只能依据 L3 配方出稿。
- 库中确无通用组件：ResultBar、通用 Tooltip、通用 PageHeader、Tree、Timeline、ProductSelector，按 L5「未建组件降级规则」处理。
