# Figma 组件文档模板（写给 AI 的「Figma 调用说明书」）

> 用途：给每个组件写一份"AI 能照着在 Figma 里出稿"的说明。
>
> **重大变更（2026-06-18）**：项目范围收敛为 **Figma-only**——只在 Figma 搭组件库，AI 通过 Figma MCP 直接出稿，不再产出 React/Storybook/Code Connect。本模板据此从"代码视角"改写为"Figma 视角"。旧的代码版模板见备份。
>
> 黄金示例：[`Button.usage.md`](../L2_组件/components/Button/Button.usage.md)

---

## 🎯 目标

让任何 AI 拿到用户需求（"我要一个商品列表页"），能**自主**完成：

- 用哪些组件 ← 看「组件目录」+ 各组件「2. 何时用」
- 用哪个变体 ← 看「3. 决策树」
- 变体属性怎么设 ← 看「4. 变体属性契约」（这是 MCP 在 Figma 里要设的精确字段）
- 怎么和其他组件拼 ← 看「7. 组合模式」
- 不会犯什么错 ← 看「8. 反例」

核心区别于旧版：AI 操作的对象不再是 React `props`，而是 **Figma 组件的变体属性（Component Properties）+ node-id**。

---

## 🧱 两层文档结构（借鉴 Ant Design）

Ant Design 把规范分两层，我们沿用：

| 层 | 对应文件 | 回答的问题 |
|----|---------|-----------|
| **组件层**（本模板） | `{Component}.usage.md` | 这个组件**怎么用、用哪个变体、属性怎么设** |
| **页面/全局层** | `docs/seller-center-spec.md` + 规范文档 | 跨组件规则：按钮摆放与排序、表单布局、反馈、文案、数字格式、动效… |

写组件文档时只管组件层；跨组件的通用规则**不要在每个组件里重复**，统一放页面/全局层并互相链接。

## 📂 文件位置约定

文档就近放在组件资料夹里，文件名 `{ComponentName}.usage.md`：

```
figma-library/                 # （Figma-only 后此目录仅存文档 + 图标/插画 svg 资产）
├── docs/
│   └── seller-center-spec.md         ← 组件目录索引 + 跨组件/页面级规则
└── src/components/{Name}/
    ├── {Name}.usage.md               ← 本模板针对这个
    └── (Icon/ 与 Illustration/ 目录保留 svg 资产)
```

> 建议：条件允许时，把同样的说明做成 Figma 文件里组件画板旁的「Usage」frame，这样 MCP 读文件即可见，无需额外读 .md。

## 📐 文档模板（复制下面，把 `{ComponentName}` 替换为目标组件名后逐节填）

```markdown
# {ComponentName} 组件用法（AI 调用指南）

> 写给 AI 的"按这个在 Figma 里调用就对了"的说明书。
>
> **依据来源**：
> - **主**：System Test 里的 {ComponentName} 组件（变体清晰、Token 完整）—— [Figma 节点 X:Y](https://www.figma.com/design/KTvcllui6OGgNPI5f1DfHe/System-Test?node-id=X-Y)
> - **辅**：旧 Shopee Guidelines（仅提取仍适用的 Shopee 特有规则；分类体系不沿用）
>
> 跨组件/页面级规则见 [docs/seller-center-spec.md]。

## 1. 总览

- **Figma 组件名**：`{ComponentName}`（与 Figma 图层名完全一致，PascalCase）
- **node-id**：`X:Y`（ComponentSet 根节点；MCP 用它定位）
- **用途**：一句话说清什么时候用（要能和相邻组件区分开）
- **变体维度**：列出维度，如 `Type(5) × Size(3) × State(5)`
- **依赖的基础组件**：引用了哪些已建组件（含 node-id），如 `Icon (40:2)`

## 2. 何时用 / 何时不用（When to use）

- ✅ 在以下情况用本组件：……（带具体场景词）
- ❌ 不要用本组件，改用 X：……（点名最容易混淆的相邻组件 + 区分判据）

> 写法学 Ant：给可判定的边界。例：「选项 2–5 个用 Radio，超过 5 个改用 Dropdown」。

## 3. 决策树（AI 必读）

  用户需要 X 场景?
  ├─ 子场景 A（具体场景词：提交/保存/确定…） → Type=Primary, Size=Default
  ├─ 子场景 B（取消/返回/重置…）            → Type=Outline
  └─ 子场景 C（表格行内次级操作…）          → Type=Text, Size=Small
  特殊情况（危险/加载/仅图标…）?
  └─ → 设对应属性

（每个节点 = 一个判断问题 + 具体场景词 + **具体变体属性组合**，AI 顺着走就能定属性）

## 4. 变体属性契约（= Figma Component Properties）

> 这是 MCP 出稿时要设置的**精确字段**，替代旧版的 React props 表。

| 属性名 | 属性类型 | 可选值 | 默认 | 绑定 Token | 说明 |
|--------|---------|--------|------|-----------|------|
| `Type` | Variant | Primary / Outline / Default / Text / Link | Default | — | 视觉强调级别 |
| `Size` | Variant | Small / Default / Large | Default | `Components/{X}/size*` | 高度 24/32/40 |
| `State` | Variant | Default / Hover / Active / Focus / Disabled | Default | — | 交互态（出静态稿一般用 Default） |
| `Danger` | Boolean | true / false | false | `…/colorError*` | 危险修饰 |
| `Icon` | Instance Swap | 引用 Icon 库实例 | — | — | 仅从 Icon 库选，禁止自创 |
| `Label` | Text | 任意（demo 用英文） | "Button" | — | 按钮文字 |

> 💡 类型说明：Variant=变体维度；Boolean=开关；Instance Swap=替换子实例（必须引用现有组件）；Text=文本属性。

## 5. 视觉规格（全部引用 Token，不写死值）

| 维度 | 值 | Token |
|------|----|----|
| 高度 (Default) | 32px | `Components/{X}/controlHeight` |
| 水平内边距 | 15px | `Components/{X}/paddingInline` |
| 字号 | 14px | `…/fontSize` → `fontSize` |
| 焦点环 | 内白+外橙 30% | `--boxShadowFocusPrimary` |

## 6. Shopee 特有规则（来自旧 Guidelines，⭐ 高价值）

列出旧规范里**仍然有效**、别处通常没有的 Shopee 智慧（对齐方式、数量上限、特殊流程等）。

## 7. 组合模式

| 场景 | 本组件配置 | 配合组件（node-id） | 排布 |
|------|-----------|--------------------|------|
| … | Type=Primary | Form / Input | 左对齐 |

## 8. 反例（AI 绝不能这样做）

| ❌ 错误 | ✅ 正确 | 原因 |
|---------|---------|------|
| … | … | **原因必须解释"为什么错"**，不能只说"不对" |

> 条件允许时，在 Figma 画板上摆一对 Do/Don't 示例 frame，比文字更直观。

## 9. Token 主题化

| 需求 | 改哪个 Token |
|------|-------------|
| 提升整体圆角 | `Components/{X}/borderRadius` |
| 换主色 | `Components/{X}/colorPrimary` |

## 10.（选填）动效 / a11y

Phase 1 可略；后续补充。

## 文档维护历史
- YYYY-MM-DD：变更摘要
```

## ✍️ 写作准则（质量关键，沿用旧版经验）

### 必填 vs 选填

| 节 | 重要性 |
|----|--------|
| 1 总览 / 2 何时用 / 3 决策树 / 4 变体属性契约 | 🔴 必填（缺了 AI 没法出稿） |
| 5 视觉规格 / 6 Shopee 规则 / 7 组合 / 8 反例 | 🟡 强烈推荐 |
| 9 Token / 10 动效·a11y | 🟢 锦上添花 |

最低标准：**1–4 节必填**。

### 决策树要"可判定"

❌ 不好：「primary 用于主操作，outline 用于次要操作」——AI 还是不知道自己的场景算哪种。
✅ 好：「是页面主 CTA（提交/保存/确定/创建/购买）？→ Type=Primary，同区域最多 1 个」——带场景词 + 具体属性 + 硬规则。

### demo 文字一律英文

组件库是底层基础，被多语言业务消费。所有示例里的按钮文字、占位符、表格内容用英文（`Add Product`、`On Sale`），业务接入时再 i18n。

### 变体属性契约要对齐真实 Figma

属性名、可选值必须和 Figma 组件里的 Component Properties **逐字一致**（含大小写），否则 MCP 设属性会失败。用 `get_metadata` / `get_design_context` 核对，别凭记忆写。

### 反例的「原因」列要讲透

❌ 只写"应该用组件"；✅ 写"`<a>` 在屏幕阅读器中被识别为链接，暗示导航，而按钮触发的是操作，语义错误"。

## 🤖 给新会话 AI 的快捷指令（写某组件文档时）

**依据优先级**：
1. **主**：System Test 里该组件的真实实现（变体属性、Token 绑定）—— single source of truth
2. **辅**：旧 Guidelines——仅提取仍适用的 Shopee 特有规则，不被旧分类绑架
3. **兜底**：Ant Design / 通用最佳实践——仅当上面都没说时

**执行步骤**：
1. 读 [`Button.usage.md`](../L2_组件/components/Button/Button.usage.md) 当格式参考
2. 在 Figma 读本地变量 `Components/{X}/*`（用 `use_figma`）看该组件有哪些 Token
3. 用 `get_metadata` + `get_screenshot` 看 System Test 里该组件的变体属性与外观
4. （如有）看旧 Guidelines 对应章节，提取 Shopee 特有智慧
5. 在 `src/components/{X}/{X}.usage.md` 按模板填，**4. 变体属性契约**逐字对齐 Figma
6. 同步 `docs/seller-center-spec.md` 组件目录：⏳ 改 ✅ + 加 node-id 链接

**写完自查**：
- 4. 变体属性契约的属性名/可选值和 Figma 完全一致？
- 决策树每个分支都给了具体变体属性组合？
- 是否复用了现有 Icon / 基础组件（没自创）？
- 反例的"原因"列讲透了？
