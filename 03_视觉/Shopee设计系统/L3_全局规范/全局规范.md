# L3 全局规范

> **AI 出稿的入口文件。**先读本文件定页面骨架，再按 [`../L2_组件/组件索引.md`](../L2_组件/组件索引.md) 取具体组件。
>
> 本层只处理**多个组件一起出现时**的规则。单组件用法在 L2，具体数值在 L1。
>
> 合并自原 `seller-center-spec.md` §二 §四 与 `通用体验规则草案.md`。

## 一 总则

1. **只用库内组件，不自创**——找不到精确组件时，先考虑用现有组件组合，再考虑新建并入库。不直接画裸形状。
2. **不写死值，一律绑 Token**——颜色、间距、圆角、字号全部引用变量。数值出处见 L1。
3. **复合组件必须复用基础组件**——Filter 里的下拉/搜索是已建组件的实例，不另画。
4. **图标只从 Icon 库取**，不自创 SVG；缺图标先入库再用。
5. **组件必须显式设置变体属性**，不依赖默认变体。
6. **真实业务文案必须覆盖默认占位文字**——用 `Add Product`，不保留 `Button`。
7. **仅 desktop、仅 light、仅 EN**——响应式只考虑浏览器宽度自适应。

## 二 页面骨架配方

拿到需求先判断页面类型，套配方定骨架，再按 L2 索引取具体组件。

| 页面类型 | 典型需求词 | 骨架（从上到下） |
|---|---|---|
| 列表 / 管理页 | 商品列表、订单管理 | Header → Sidebar → PageHeader → Breadcrumb → Filter/Search → Toolbar(批量) → ResultBar → Table → Pagination |
| 表单 / 创建编辑页 | 新建商品、编辑资料 | Header → Breadcrumb → Form(Input/Select/DatePicker/Upload) → 底部 Button 组（左对齐） |
| 详情页 | 订单详情、商品详情 | Header → Breadcrumb → Card 分区（基本信息/明细）→ 操作 Button → Tabs（分栏时） |
| 仪表盘 / 概览页 | 数据概览、Dashboard | Header → MetricsCard 组(KPI) → Filter(时间/维度) → Chart / Table（图表选型见 [`图表选型.md`](../../develop-visual-solution/references/图表选型.md)） |
| 弹层任务 | 确认删除、快速编辑、筛选面板 | Modal（确认/表单）/ Drawer（侧滑长表单）/ Popover（轻量） |
| 空 / 异常态 | 暂无数据、无权限、加载中 | DefaultPage（空状态）/ Alert（提示）/ Spin（加载）/ Skeleton（占位） |

**两条硬要求：**

- 页面必须先搭骨架再填内容。列表页不能只堆 Filter + Table，AppShell、PageHeader、ResultBar、Pagination 都要考虑到。
- 有页面模板时优先从模板起手（见 L4）。没有模板时按上表配方搭。L2 的单组件文档只解决单组件问题，不能替代骨架。

找不到对应配方时，把页面拆成导航 / 录入 / 展示 / 反馈四类，分别取组件。

## 三 按钮排布

- **强调唯一**：一组按钮里最多 1 个 Primary；没有主操作时全用 Default/Outline。
- **同区域最多 1 个 Loading。**
- **对齐**：表单底部左对齐；表格批量与表尾右对齐；弹窗底部居中或右对齐；卡片右上角单按钮右上对齐。
- **顺序**：取消/返回在左，主操作在右。
- **数量**：同区域超过 3 个时保留 2–3 个，其余收入 Dropdown。
- **危险操作**：需二次确认，不直接裸露执行。入口用 `Outline + Danger`，确认弹窗内用 `Primary + Danger`。文案要表达后果。

---

## 四 表单布局

- 字段水平间距 `size`(16)，垂直间距 `sizeMD`(20)。
- label 左置为默认；文案过长或英文语境可置顶，但全系统保持一致。
- 提交 = Primary，取消 = Outline 且在左；异步提交时主按钮进 Loading 态。
- 校验错误就近显示在字段下方；整页错误或风险用顶部 Alert 汇总。
- 必填项必须有明确标记。
- 重要说明常驻可见，不要只放在 placeholder 里。

## 五 反馈层级

| 场景 | 用什么 |
|---|---|
| 操作结果（成功/失败） | Toast，自动消失，不打断 |
| 页面常驻状态或风险 | Alert，条状，可带操作 |
| 需要确认或输入的中量任务 | Modal |
| 长表单 / 侧栏详情 | Drawer |
| 悬浮轻量信息 | Tooltip / Popover |
| 整块加载 | Spin |
| 列表/卡片首次加载 | Skeleton |
| 空 / 异常 | DefaultPage（配 Illustration + 一个引导 CTA） |

加载态不使用随意文字占位。

## 六 颜色语义

**每个语义角色都是一整套 10 个变体，不是单个颜色。** 主体 / Hover / Active / Bg / BgHover / Border / BorderHover / Text / TextHover / TextActive。

| 角色 | 主体 Token | 用途 |
|---|---|---|
| Primary | `colorPrimary` | 主操作、品牌强调 |
| Success | `colorSuccess` | 成功、正向 |
| Warning | `colorWarning` | 警告、需注意 |
| Error | `colorError` | 错误、危险 |
| Info / Link | `colorInfo` / `colorLink` | 信息、链接 |

中性色（文本、图标、背景、边框、填充）用 Neutral 一组：`colorTextHeading` / `colorText` / `colorTextSecondary` / `colorTextTertiary` / `colorIcon` / `colorBgContainer` / `colorBgLayout` / `colorBorder` / `colorSplit` / `colorFill*`。

做 hover、按下、禁用、浅底时用该角色已有的变体，**不调透明度、不换色阶**。完整 token 表与色值见 [`../L1_原子变量/README.md`](../L1_原子变量/README.md)。不写裸色值，不直接引用 Base 调色板。

## 七 间距节奏

| Token | 值 | 用途 |
|---|---|---|
| `sizeXXS` | 4 | 最小间隙、图标与文字贴合 |
| `sizeXS` | 8 | 同类元素间 |
| `sizeSM` | 12 | 紧凑内边距 |
| `sizeMS` | 16 | 内容水平内边距（语义区别于 `size`） |
| `size` | 16 | 默认；表单字段水平 |
| `sizeMD` | 20 | 表单字段垂直 |
| `sizeLG` | 24 | 区块间、卡片内边距、页面边距 |
| `sizeXL` | 32 | 大区块间 |
| `sizeXXL` | 48 | 页面级大留白 |

不写魔法数字。控件高度用 `controlHeight` 四档（16 / 24 / 32 / 40），线宽用 `lineWidth` 四档（1 / 2 / 2 / 4），圆角用 `borderRadius` 四档（2 / 4 / 6 / 8）。

## 七之二 字体与阴影

- 文本优先使用 9 个命名文本样式：`Heading/xl`（24·Medium·32）、`Heading/l`（20·28）、`Heading/m`（18·26）、`Heading/s`（16·24）、`Heading/xs`（14·20）、`Body/medium`（14·Medium·20）、`Body/regular`（14·Regular·20）、`Caption/medium`（12·Medium·16）、`Caption/regular`（12·Regular·16）。
- 字号只有 6 档（12 / 14 / 16 / 18 / 20 / 24），不新增相近字号。字体族 `fontFamily` = Inter 系。
- 阴影只有 3 个 Effect Style：`boxShadow`（Popover / Tooltip / Dropdown）、`boxShadowSecondary`（Modal / Drawer / Popconfirm）、`boxShadowTertiary`（保留）。整体套用，不手写单层阴影。

---

## 八 文案

- 英文，动词开头，简洁。
- 名词用业务词（Product / Order / Shop）。
- 按钮文案用动词开头，短而明确。
- 危险操作文案要表达后果。
- 业务页面必须使用真实业务词，不保留组件默认占位。
- 数字、金额、百分比、日期与时间格式见 [`数字与日期规范.md`](数字与日期规范.md)。**格式按站点变化**——ID 与 VN 的小数点和千分符与其他站点相反，PH 是月/日/年，TW 是年/月/日，写错就是错。

---

## 八之二 动效

**时间以 100ms 倍增：最快 100ms、基本 200ms、较大 400ms。** 不使用这三档之外的随意数值。

**三条缓动曲线：**

| 类型 | 曲线 | 何时用 |
|---|---|---|
| 缓出 | `cubic-bezier(0, 0, 0.58, 1)` | **交互性操作优先用这类**——初始速度快，能有效反馈用户操作 |
| 缓入 | `cubic-bezier(0.42, 0, 1, 1)` | 元素飞出、组件渐隐或消失 |
| 缓入缓出 | `cubic-bezier(0.42, 0, 0.58, 1)` | 可视范围内点到点的运动，如组件展开收起 |

**常见场景：**

| 场景 | 缓动 | 时长 |
|---|---|---|
| 表单内容加载 | 缓入缓出 | 300ms |
| 表单信息新增 | 缓入缓出 | 300ms |
| 选项框动画 | 缓出 | 100ms |
| 下拉选择 | 缓入缓出 | 200ms |
| 弹窗进场 | 缓入，从下往上渐显 | 300ms |
| 弹窗关闭 | 缓入缓出，往上渐隐 | 200ms |

原则：动效必须有目的、助力交互，**易用性优先级高于创意形式**，不做增加阅读难度的修饰动画。

## 八之三 键盘与鼠标交互

见 [`键鼠交互规范.md`](键鼠交互规范.md)。要点：Tab 顺序与视觉顺序一致；初始焦点不放在「删除」「否」这类破坏性操作上；弹层可用 ESC 关闭；浏览器中不建议把右键菜单或双击作为唯一入口。

## 九 消歧速查

最容易选错的几对：

- 即时操作用 Button；纯页面跳转用 `Button Type=Link` 或链接文本。
- 选项 2–5 个用 Radio / Checkbox；超过 5 个用 Dropdown / Select。
- 弹层：轻量信息悬浮用 Tooltip / Popover；需要操作或表单的中量任务用 Modal；长表单或侧栏用 Drawer。
- 反馈：操作结果短提示用 Toast；页面常驻状态条用 Alert。
- 状态标记用 Tag；数字或红点角标用 Badge。

## 反例

| 错误 | 正确 | 原因 |
|---|---|---|
| 列表页只放 Filter + Table | 补齐 AppShell / PageHeader / ResultBar / Pagination | 缺骨架是首次出稿的主要失败点 |
| 沿用组件默认变体 | 显式设置全部变体属性 | 默认变体多为 Primary，会出现多个主按钮 |
| 保留 `Button`、`Text` 等占位文案 | 替换为真实业务文案 | 占位文案使页面无法评估 |
| 一个区域出现 2 个以上 Primary | 只留最重要的 1 个 | 视觉焦点必须唯一 |
| 表单按钮右对齐 | 表单左对齐 | 视线跟随字段左边线 |
| 危险操作直接执行 | 套二次确认 | 破坏性操作必须可撤回 |
| 用文字"加载中…"占位 | Spin 或 Skeleton | 加载态有专用组件 |
