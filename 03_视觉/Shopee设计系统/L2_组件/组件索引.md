## 引用方式

⚠️ **优先使用 `componentKey`，不要用 node-id 找组件。**

`componentKey` 是 library 组件的稳定标识，组件在画布上移动、重排、改页面都不会变；node-id 会变，也容易误取到组件展示页 / Display frame 而不是 ComponentSet 根，用错会实例化错对象。

本文件的 `componentKey` 列于 **2026-08-09** 通过 Figma MCP 对库逐项核验。node-id 为历史记录且多数已失效，2026-08-10 起不再保留，需要时在 Figma 中现取。

## 文档维护

🚨 **在 Figma 里建完组件，必须立刻回来更新本文件——这是硬规则，不是建议。**

只在 Figma 建、不更新索引，会让整条流程继续以为这个组件不存在，进而在 L3 骨架、L4 拆解和 L5 检查项里连锁传播错误信息。**Toolbar 就是这么出事的**：2026-07-10 已在 Figma 建成，索引一直标 ⏳，一个多月里 L4 把它列为"P0 待新建"、L3 骨架要求用它、L5 要求列表页必须有它，最后变成"列表页永远交付不了"的死锁。

新建组件后必须完成三件事，缺一不可：

1. **Figma 里建**（按 `_建设参考/导入新组件的完整流程.md` 的 Phase 1–4；该资料已于 2026-08-10 移出包，归档在包外 `Design-loop-归档/_建设参考/`）
2. **回本文件更新索引**：状态 ⏳ → ✅ 或 🔷，补上 `componentKey`，若属于列表/表单骨架件还要同步 L3 与 L5 的相关条目
3. **写 usage 文档**：按 `_建设参考/组件文档模板.md`（归档位置同上）。可以延后——先标 🔷，变体属性直接读 Figma 也能用；但第 2 步不能延后

- 新建组件后：按 `_建设参考/组件文档模板.md` 写 usage 文档，并在本文件把状态改 ✅ + 补 `componentKey` + 补链接。
- **每次 library 有较大更新后，必须对本文件做一次逐项对账**，不能只在新建组件时追加。索引长期未对账是本文件历史上最大的失效来源。
- 冲突一律以 Figma 为准。变体属性与 Token 现读 Figma，不在文档内复制契约表。

完整清单与建设进度见 `_建设参考/组件清单.xlsx`（归档位置同上）。
