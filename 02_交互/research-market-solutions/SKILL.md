# 市场产品方案研究

## 入口硬门禁（第一动作，未执行作废）

进步骤第一动作：**读取 Case 的 `需求总结`（状态卡）并对齐**。核对 🔒 字段——目标端、视觉基线（参考 Figma）、产品逻辑八项——逐项确认与记忆一致，不一致以状态卡为准。**未读取状态卡不得开始本步骤**；发现需改 🔒 字段时退回 Step 1，不得自行调整。

## 输入

- Step 1 已确认的现状、痛点、目标和预期方案
- **Step 1 已确认的`产品逻辑`**（八项定义见 [`需求总结模板`](../../04_Case归档模板/01_需求澄清/需求总结模板.md)）
- **Step 1 已确认的`目标端`**（Seller Centre Web / Seller APP / Shopee APP / 多端）
- Step 1 已读取的现有 Figma 页面上下文（降级时为截图、文字与 L4 拆解）
- 可选：已知竞品、平台限制、业务规则和技术约束

Figma 页面只用于理解当前产品和约束，不作为市场证据。无 Figma（视觉基线待补）时，用 Step 1 降级依据（截图/文字/L4）替代"现有 Figma 页面上下文"。

**用`产品逻辑`筛选竞品机制**：竞品机制的触发条件或频次与本次不同时，只可借鉴其表达方式，不得连同触发逻辑一起照搬；记录借鉴点时写明差异在哪。多端需求按端筛选，不混用各端机制。

## 内部交接

- 市场方案类型及代表案例
- 每类方案的运行机制、适用条件、优点和缺点
- 当前项目机会
- 给方案发散阶段的方向约束
- 每个候选方案可直接使用的研究借鉴点与来源

## 强制调用

1. 完整读取并调用包内 [`agent-reach`](../agent-reach/SKILL.md)，用于公开网页、产品文档、评测、社区和视频证据。
2. 调用 Mobbin 的 screen 与 flow 搜索能力，用于真实页面、状态和流程证据。
以上两项不得跳过。任一项未成功调用时，明确记录缺口并继续补齐；未达到本 Skill 输出标准前不得交给下一阶段。

**双源断线自动降级**：Mobbin 与 Agent Reach **都**已实际调用（含自动诊断与安全重试）且都失败、且无登录/OAuth/权限类需用户操作的事项时，自动降级为「无外部证据」档：写标记 `市场证据来源：自动降级无外部证据（双源断线）`，用一句话告知用户，方向改为从现有页面/截图、Step 1 痛点和产品约束反推，**不得编造来源**，不无限等待补齐研究。

## 工作流

### 1. 建立研究简报

从已确认需求中提取：

- 用户要完成的任务
- 触发场景
- 关键对象和决策
- 已知约束
- 成功目标
- 3–6 个研究问题

不要改写产品目标。存在关键缺口时只问一个问题。

### 2. 检查来源能力

1. 确认 Step 0 已验证 Mobbin 可用于查看 screen 或 flow。
2. 完整读取已安装的 `agent-reach` Skill，并**实际调用一次搜索**（通用搜索或网页阅读）验证可用；调用结果摘要写入 Case 回执。未实际调用不得声称已使用 agent-reach。
3. Mobbin 不可用时先自动检查工具发现、MCP 安装与配置、连接状态、授权 scope、订阅权限、地区限制和日志，并在安全范围内重试；只有登录、OAuth、权限或管理员审批必须由本人完成时才暂停请求用户操作。
4. 登录墙、地区限制或页面不可用且自动恢复失败时，记录证据限制。

**最小可用配置**：agent-reach 只需「通用搜索 + 网页阅读」两个 channel 即可启动 Step 2；社交、视频等 channel 按需启用，不作为启动前置。未启用 channel 标注"未配置"，不阻塞。

任一主要来源不可用时，明确标记证据覆盖不足，不假装完成双来源研究。

### 3. 建立可比对象

按以下顺序寻找，**只保留前 3 档进入画板**（直接/任务/机制同类）；第 4、5 档（约束同类、反面案例）只入内部记录，不进画板，没有可展示的直接同类就跳过、不硬凑：

1. 直接同类：相同用户、任务和业务约束。
2. 任务同类：行业不同，但用户任务相同。
3. 机制同类：使用相同的决策、反馈或控制机制。
4. 约束同类：面对相同的风险、权限或复杂度。
5. 反面案例：能说明某种做法为何失效。

### 4. 收集证据

Mobbin 用于确认真实页面、状态和流程。Agent Reach 用于补充：

- 官方产品页、帮助中心和更新日志
- 独立评测和案例研究
- 用户反馈、社区讨论和视频演示
- 必要的权限、数据或技术边界

不得仅凭搜索摘要描述产品行为。

### 5. 归纳方案类型

聚合为 2–5 类互相可比较的方案：

- 运行机制
- 代表产品与证据
- 适用条件
- 优点
- 缺点与代价
- 失败条件
- 证据强度

按“方案如何工作”分类，不按 Mobbin、网页、App 或产品名称分类。

### 6. 提炼当前项目机会

结合现有 Figma 页面和产品约束，输出：

- 可借鉴的机制及成立前提
- 不建议照抄的做法及原因
- 当前项目可以重点解决的机会
- 后续粗方案必须回答的问题

机会只描述目标、矛盾和判断标准，不规定控件、布局或视觉形式。

## 用户可见输出

- 默认不单独向用户展示市场研究报告。
- 研究结论写入 Case 内部记录（`02_竞品调研/`），供 `build-rough-prototypes` 生成画板时作为借鉴点使用；产品名和必要的原始术语可以保留英文。
- 画板只呈现结论性借鉴点，不占画板独立区块：按 `build-rough-prototypes` 的「固定画板格式」约定，研究机制、来源和当前项目机会保留在内部记录；只有推荐成立必须依赖该证据时，才压缩进推荐理由的一句话。
- 只有来源不可用或证据不足以支撑方案时，向用户输出一句阻塞说明。

## 边界

- 不修改 Step 1 已确认的产品目标。
- 不替当前项目选择最终方案。
- 不生成页面结构、HTML、Figma 或视觉规范。
- 不把竞品普遍采用等同于适合当前项目。
- 不虚构产品、截图、来源、用户评价或效果数据。
- 不下载、保存或归档竞品图片到本地。

## 完成标准

- **标记为「已连接」时**：Mobbin 与 Agent Reach 均已实际调用；无法调用的能力已修复或明确阻塞，不能被静默跳过。**标记为「用户确认无证据」或「自动降级无外部证据」时**：本项不适用，跳过并在回执记录。
- 内部研究交接包含方案类型、适用条件、优点、缺点和当前项目机会。
- **标记为「已连接」时**：每个保留的交互方向都能对应至少一个真实研究机制、来源与适用理由。**标记为「用户确认无证据」或「自动降级无外部证据」时**：方向改为从现有页面/截图、Step 1 痛点和产品约束反推，画板如实标注「本方向无外部市场证据，依据：现有页面 + 痛点反推」，**不得编造来源**。
- 研究结论已写入 Case 内部记录，且与 `build-rough-prototypes` 的固定画板格式一致（不占画板区块）。
- 多端需求：研究机制按目标端分别对应，不混用各端证据。

未达到任一项时，继续在市场调研阶段补齐，不进入方案发散。

## Token 规则

- 研究问题由 AI 自行提出并在内部解决，不向用户逐项追问。
- 搜索以方案机制和关键风险为单位停止，不为凑数量继续。
- 最终只把能指导方案的结论传给后续 Skill。
