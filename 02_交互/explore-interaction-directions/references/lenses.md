# 认知视角表

视角不是角色，也不是领域专家。它是一个**刻意的扭曲**，把问题从另一个位置重新提问，逼生成器走进它不会自然漂过去的角落。

默认每轮选 3 个；发散不足时扩展到 5 个。规则：至少 1 个结构类、至少 1 个越界类，同一问题重跑时换一批。

---

## 结构类 —— 改变信息组织或流程形态

这几个最容易产出"方向真的不同"的方案，每轮至少选一个。

| 视角 | Vantage prompt |
|---|---|
| **拿掉承重假设** | 说出这个问题里所有人默认不变的那个东西——某个页面、某个步骤、某个必填项、"用户必须先选 X 才能 Y"。假设它不存在。现在怎么做？ |
| **反过来问** | 问相反的问题。如果目标是让用户高效完成 X，先头脑风暴"怎样保证他绝对完不成 X"。列完再逐条取反。 |
| **压缩到一步** | 整个流程只允许一次交互。用户点一下就完事。什么必须被系统推断、被默认、被延后、被砍掉？ |
| **拆成一串** | 反过来，把它拆成尽可能多的小步骤，每步只做一件事、只问一个问题。什么时候这反而更好？ |
| **换个容器** | 这件事如果不发生在当前这个页面里——发生在列表行内、悬浮层、独立页、消息里、别人的产品里——分别长什么样？ |
| **谁来发起** | 现在是用户主动发起。改成：系统建议、系统自动做完再告诉用户、别人代他做、定时触发。各是什么形态？ |

## 用户类 —— 换一种人来用

| 视角 | Vantage prompt |
|---|---|
| **第一次用的人** | 你从没见过这个产品，不知道任何术语和惯例。你会怎么理解这个任务？什么地方会让你卡住或误解？由此设计。 |
| **每天用 200 次的人** | 你是重度用户，闭着眼睛都能操作，最恨多余的确认和动画。你要什么？快捷方式、批量、记忆、跳过。 |
| **不看说明的人** | 用户不读任何提示文案、不看引导、不点问号。界面本身必须自解释。什么必须靠形态和位置说清楚？ |
| **不想用的人** | 用户被迫来做这件事，只想尽快离开。怎么让他最快脱身？什么可以事后再补？ |
| **代别人操作的人** | 操作者不是受益者（客服帮卖家、下属帮老板）。他缺少上下文，怕做错。这改变了什么？ |

---

## 对抗类 —— 从失败反推

| 视角 | Vantage prompt |
|---|---|
| **让它失败** | 你要让这个设计出丑。什么输入、什么时机、什么用户行为能让它崩掉、让人看不懂、让人做错决定？列完再逐条反推成设计。 |
| **凌晨三点** | 出事了，用户在最糟的状态下用这个功能——着急、数据异常、网络差。什么设计能让他不出错？ |
| **最坏的数据** | 数据是空的、是超长的、是一万条、全是重复的、全是异常值。每种情况下这个方案还成立吗？由此设计。 |
| **竞争对手** | 你是竞品，要拿这个功能当反面教材。你会怎么嘲笑它？由此反推该怎么做。 |

---

## 越界类 —— 明显不保守，每轮至少一个

这几个的作用不是直接产出可用方案，而是**打破保守区间**——它们经常会催生出旁边那个可行但没人想到的方案。

| 视角 | Vantage prompt |
|---|---|
| **零成本** | 没有开发资源，一小时上线，只能改文案和已有组件的排列。最粗暴但仍解决核心问题的版本是什么？ |
| **无限资源** | 无限工程、无限数据、十年时间。最激进的版本长什么样？然后：其中哪一小块今天就能做？ |
| **十岁小孩** | 你是个没见过软件的十岁小孩。用你能理解的方式描述这件事该怎么办。忽略一切行业惯例。 |
| **拿掉屏幕** | 如果没有图形界面——只能靠一句话、一个通知、一次对话完成——这件事怎么办？再把它翻译回界面。 |
| **游戏设计** | 把用户当玩家。这里的循环是什么？摩擦在哪、奖励在哪、存档点在哪、有没有速通路径？ |
| **实体世界** | 如果这件事发生在实体世界——柜台、表单、排队、货架、便利贴——它长什么样？照搬那个机制。 |

---

## 领域类 —— 移植别处的机制

| 视角 | Vantage prompt |
|---|---|
| **物流** | 偷物流的机制：排队、批处理、准时制、集散中心、退货通道。字面地套到这个问题上。 |
| **编辑器** | 偷编辑器的机制：撤销重做、草稿、版本、多选、批量替换、快捷键、命令面板。 |
| **对话** | 偷对话的机制：轮次、澄清提问、上下文记忆、打断、确认理解。 |
| **地图导航** | 偷导航的机制：当前位置、路线预览、剩余距离、偏航重算、备选路线。用户在流程里知道自己在哪吗？ |

---

## 怎么选

**问题类型 → 建议配比**

- **流程改造**（改现有流程）：结构类 1 + 对抗或用户类 1 + 越界类 1
- **从零设计**（新功能）：结构类 1 + 用户类 1 + 越界类 1
- **优化现状**（体验不好但说不清）：对抗类 1 + 结构类 1 + 越界类 1
- **信息展示**（怎么组织内容）：结构类 1 + 用户或领域类 1 + 越界类 1

扩展到 5 个时，在以上组合中补充 2 个未使用类别的视角。

**重跑时**：换掉至少 3 个视角，否则会得到相似的候选集。

## 自己加视角

一个好视角要满足至少两条：

1. **独特词汇**——用其他视角不会用的概念（存档点、偏航重算、集散中心）
2. **独特姿态**——对抗 / 天真 / 极端 / 建设性，不只是换个领域说同样的话
3. **可复现的扭曲**——稳定地产出其他视角出不来的想法

写法就是一行 vantage prompt，用第二人称，给出发点不给答案。
