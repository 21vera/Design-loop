# 链路完整性规则

分两层。**规则层是机械判定的，答案唯一，不需要品味**；判断层需要人。混在一起就会得到"看起来通过了但其实没查"的结论。

---

## 建模格式

先把方案写成状态清单，再查规则。跳过建模直接走查会漏——漏的正是没想到的分支。

### 状态表

| 状态 | 入口 | 用户操作 | 操作去向（成功/失败） | 退出（前进/后退/取消） |
|---|---|---|---|---|
| 商品列表 | 侧栏导航、首页卡片 | 筛选、搜索、点行、批量选 | 筛选→列表(已筛)/无匹配态<br>点行→详情页/加载失败 | 前进→详情<br>后退→无<br>取消→无 |

**规则：不确定的地方写 `?`，不要脑补填上。`?` 就是设计缺口，是这一步最有价值的产出。**

### 边界状态清单

这六类每个都要明确"有定义 / 未定义"：

| 边界 | 说明 | 状态 |
|---|---|---|
| 空态 | 一条数据都没有 | |
| 首次 | 第一次使用，无历史无配置 | |
| 超量 | 数据超多、文字超长、选项超多 | |
| 无权限 | 看得到但不能操作，或看不到 | |
| 加载/失败 | 加载中、网络失败、超时 | |
| 中断恢复 | 中途退出，再进来落在哪 | |

---

## 规则层（机械判定）

逐条查。这些是图的性质,答案唯一。**每条只回答"违反/未违反",不做程度评价。**

### R1 死胡同
存在状态没有任何退出方式（前进、后退、取消全无）。

判定：状态表"退出"列三项全为空或全为 `?`。

### R2 不可达
存在状态没有任何入口。

判定：状态表"入口"列为空，且不是流程起点。

### R3 缺反馈
存在用户操作没有定义结果去向。

判定："操作去向"列中，某操作缺少去向定义。

### R4 缺失败路径
可能失败的操作只定义了成功分支。

判定：涉及网络请求、外部依赖、校验、权限的操作，"失败"分支为空。
注：纯前端的展开/折叠不算。

### R5 缺恢复路径
失败态或异常态没有回到正常流程的路径。

判定：错误状态的退出去向为空，或只有"关闭"而没有重试/替代路径。

### R6 缺回头路
多步流程中存在无法后退的步骤。

判定：步骤数 ≥ 2 的流程中，某步"后退"为空且不是首步。
例外：已提交的不可逆操作，但此时必须有 R7 定义。

### R7 中断丢失
没有定义中途退出后再进来落在哪。

判定：涉及多步或表单填写的流程，"中断恢复"未定义。
必须回答三件事：数据保留吗、落在哪一步、用户知道吗。

### R8 边界缺失
上述六类边界有未定义的。

判定：边界状态清单中存在"未定义"。

### R9 孤立分支
某分支走完后回不到主流程。

判定：某状态的所有出边都指向该分支内部，无法返回主路径。

### R10 状态爆炸
单个状态的操作组合超过 8 种。

判定：操作数 × 状态变体数 > 8。
含义：该拆成多个状态，或该收起部分操作。

## 判断层（需要人）

规则层查完之后再做这部分。带一个具体用户目标从入口走到底。

每一步问四个问题：

1. **定位**——用户知道自己在哪、在整个流程的什么位置吗？
2. **下一步**——知道该做什么吗？主操作是否明确？
3. **退路**——如果这不是他想要的，知道怎么退吗？
4. **决策信息**——这一步做决定所需的信息，此刻都在眼前吗？

**这一层只列可疑点，不给通过/不通过判定。** 它没有客观标准，属于人评范围。

## 内部输出格式

以下内容供 AI 自检和传递给 HTML 制作。完整状态表和规则结果不向用户展示；只把与当前任务相关的边界压缩成画板中的简短中文标注。

### 1. 状态清单
表格，`?` 保留不填。

### 2. 规则违反
```
R1 死胡同     ✗ 「导入失败」页只有关闭，关闭后回到哪未定义
R3 缺反馈     ✗ 「批量删除」未定义成功后列表如何更新
R7 中断丢失   ✗ 三步导入流程，中途退出的行为未定义
R2/R4/R5/R6/R8/R9/R10  ✓
```
硬结论，不加"建议""可能"。

### 3. 边界覆盖
六类 × 已定义/未定义，未定义的列出来。

### 4. 走查可疑点
每条标位置和疑虑，并**明确注明这部分需要人判断**。

### 5. 建议补充的状态
只列出缺什么，不擅自设计怎么做。

### 6. 画板用的边界标注（对外唯一输出）

上面 1–5 项全部内化，不给用户看。真正进入 HTML 画板的只有这一段：每个方案一块，每条一行，简体中文。

```text
边界情况｜系统处理
────────────────
数据为空｜显示空态卡片 + "Add your first product" 按钮
批量操作失败｜顶部 Alert 汇总失败项，失败行保持勾选可重试
无权限｜入口置灰 + Tooltip 说明所需权限
加载中｜表格区 Skeleton，操作按钮 Loading 态
中途退出｜已勾选项不保留，筛选条件保留，回到列表第 1 页
```

**写法要求**

- 只写与当前任务真实相关的边界，不为凑数量罗列六类。
- 「系统处理」要写清用户会看到什么、能做什么，不写"给出提示"这种空话。
- 主流程做成可点击交互；边界默认只做这段文字标注。**只有某个边界会改变方案的核心机制、步骤或成立条件时，才把它并入主流程原型。**
- 规则层（R1–R10）判定出的违反必须先修掉，不能靠这段标注掩盖。

### 6. 画板边界标注

每个方案只保留 3–6 条会影响理解或实现的边界，格式固定为：

```text
情况｜系统处理
```

例如：

```text
发送失败｜保留当前配置并提供重试
价格或库存变化｜发送前重新校验并提示返回编辑
中途关闭｜再次进入时恢复未发送内容
```

边界标注只说明处理原则，不在粗方案阶段展开完整异常页面，也不默认要求做成可点击交互。只有边界会改变方案核心机制时，才进入主流程原型。

---

## 边界说明

本规则集判定的是**结构完整性**，不是方案质量。

一个完整的烂方案会全部通过。方案好不好属于人评，不在这里。

反过来也成立：违反 R1-R10 是硬伤，不管方案多好看。
