# 画板机械检查

粗方案 HTML 画板的自动检查。**这是全包唯一"我绕不过去"的检查**——它测的是浏览器里的真实渲染结果，不是我对截图的主观判断。

每次生成或更新画板后，在浏览器中打开画板并对**每个方案的每个关键状态**执行一次。结果写入 Case 的 `_自检回执.md`，聊天里不提。

## 分级

检查项分两级，**处理方式不同**：

| 级别 | 含义 | 处理 |
|---|---|---|
| **硬阻断** | 确定性高，几乎不会误报 | 命中即不通过，必须修完再重跑 |
| **需逐条判定** | 正常设计也会命中 | 必须对**每一条**说明是设计意图还是缺陷，写进回执。**不允许整批标"误报"** |

## 检查脚本

在浏览器中对当前状态执行：

```js
(() => {
  const vis = el => {
    const r = el.getBoundingClientRect(), s = getComputedStyle(el);
    return r.width > 0 && r.height > 0 && s.visibility !== 'hidden' && s.display !== 'none' && +s.opacity > 0.01;
  };
  const all = [...document.querySelectorAll('body *')].filter(vis);
  const out = { 硬阻断: {}, 需逐条判定: {} };

  // —— 硬阻断 ——
  out.硬阻断.文字溢出 = all.filter(el =>
    el.children.length === 0 && el.textContent.trim() &&
    (el.scrollWidth > el.clientWidth + 1 || el.scrollHeight > el.clientHeight + 1) &&
    getComputedStyle(el).overflow !== 'auto' && getComputedStyle(el).overflow !== 'scroll'
  ).map(el => el.textContent.trim().slice(0, 40));

  const imgs = [...document.images];
  out.硬阻断.图片加载失败 = imgs.filter(i => !i.complete || !i.naturalWidth).map(i => i.src.slice(-60));
  out.硬阻断.图片比例失真 = imgs.filter(i => {
    if (!i.naturalWidth) return false;
    const r = i.getBoundingClientRect();
    if (!r.width || !r.height) return false;
    const fit = getComputedStyle(i).objectFit;
    if (fit === 'cover' || fit === 'contain') return false;
    return Math.abs((i.naturalWidth / i.naturalHeight) / (r.width / r.height) - 1) > 0.02;
  }).map(i => i.src.slice(-60));
  out.硬阻断.图片清晰度不足 = imgs.filter(i => {
    const r = i.getBoundingClientRect();
    return i.naturalWidth && r.width && i.naturalWidth < r.width * 2;
  }).map(i => `${i.src.slice(-40)} 实际${i.naturalWidth}px 显示${Math.round(i.getBoundingClientRect().width)}px`);

  out.硬阻断.缺可访问名称 = all.filter(el => {
    const clickable = el.tagName === 'BUTTON' || el.tagName === 'A' ||
      el.getAttribute('role') === 'button' || el.onclick || el.hasAttribute('data-action');
    if (!clickable) return false;
    return !(el.textContent.trim() || el.getAttribute('aria-label') ||
             el.getAttribute('aria-labelledby') || el.getAttribute('title'));
  }).map(el => el.outerHTML.slice(0, 80));

  out.硬阻断.横向滚动 = document.documentElement.scrollWidth > window.innerWidth + 1;

  // —— 需逐条判定 ——
  const box = el => el.getBoundingClientRect();
  const leaf = all.filter(el => el.children.length === 0 && (el.textContent.trim() || el.tagName === 'IMG'));
  const overlaps = [];
  for (let i = 0; i < leaf.length; i++) for (let j = i + 1; j < leaf.length; j++) {
    const a = box(leaf[i]), b = box(leaf[j]);
    if (leaf[i].contains(leaf[j]) || leaf[j].contains(leaf[i])) continue;
    const ox = Math.min(a.right, b.right) - Math.max(a.left, b.left);
    const oy = Math.min(a.bottom, b.bottom) - Math.max(a.top, b.top);
    if (ox > 2 && oy > 2) overlaps.push(
      `${leaf[i].tagName}"${(leaf[i].textContent || '').trim().slice(0, 20)}" × ${leaf[j].tagName}"${(leaf[j].textContent || '').trim().slice(0, 20)}" 重叠${Math.round(ox)}×${Math.round(oy)}`
    );
  }
  out.需逐条判定.元素重叠 = overlaps;

  const TOKEN_OK = /^(rgba?\(0,\s*0,\s*0,\s*0\)|transparent|inherit|initial|currentcolor|none)$/i;
  const raw = new Set();
  all.forEach(el => {
    const s = getComputedStyle(el);
    ['color', 'backgroundColor', 'borderTopColor'].forEach(p => {
      const v = s[p];
      if (v && !TOKEN_OK.test(v)) raw.add(`${p}: ${v}`);
    });
  });
  out.需逐条判定.出现的色值 = [...raw];

  out.统计 = { 可见元素: all.length, 图片: imgs.length, 视口: `${window.innerWidth}×${window.innerHeight}` };
  return JSON.stringify(out, null, 1);
})()
```

## 判定

**硬阻断组**——任一项非空即不通过：

- `文字溢出` —— 文字被容器截断
- `图片加载失败` —— `complete` 为 false 或 `naturalWidth` 为 0
- `图片比例失真` —— 渲染宽高比与原始宽高比偏差 > 2%，且未用 `object-fit: cover/contain`
- `图片清晰度不足` —— 原始像素 < 显示宽度 × 2
- `缺可访问名称` —— 可点击元素既无文本也无 `aria-label`
- `横向滚动` —— 页面出现非预期横向滚动条

**需逐条判定组**：

- `元素重叠` —— 弹层、Tooltip、下拉、抽屉遮罩、固定表头与滚动内容重叠都是**正常设计**。但每一条都要在回执里写明属于哪种，写不出来的按缺陷处理并修复。
- `出现的色值` —— 逐条比对 [`L1 原子变量`](../../../03_视觉/Shopee设计系统/L1_原子变量/README.md) 的色值表。**底板区域不参与**（它是位图，没有 CSS 色值）。命中不在 token 表里的值，要么改成 token，要么在回执说明理由（例：命中层用 `transparent`）。

## 边界

- 只覆盖 **Step 2 的 HTML 画板**。Figma 细方案（Step 3 / Step 4）跑不了脚本，只能走截图比对 + 落盘回执，属于较弱的约束强度，不要把两者混为一谈。
- 脚本测的是**当前渲染状态**。必须切到每个方案、每个关键状态各跑一次，只跑首屏不算完成。
- 脚本通过 ≠ 画板合格。它只覆盖能机械判定的部分；机制差异、研究映射、推荐理由、信息层级仍然要按 [`SKILL.md`](../SKILL.md) 的完成标准人工核验。
