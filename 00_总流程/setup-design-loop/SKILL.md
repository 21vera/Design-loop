# 安装 Design Loop

## 执行顺序

1. 完整读取 [`references/依赖清单.md`](references/依赖清单.md)。
2. 完整读取 [`references/自动连接Figma与Mobbin.md`](references/自动连接Figma与Mobbin.md)。
3. 检查包内文件和 Skill 是否齐全。
4. 安装或更新包内 Skill。
5. 自动发现、安装、配置并连接 Product Design、Figma、Mobbin 和 Agent Reach，再验证是否真正可用。
6. 仅在登录、OAuth 同意、权限批准、验证码、安全密钥或管理员审批必须由本人完成时暂停；先自动打开对应页面或弹窗，再明确告诉用户当前只需完成的一个动作。
7. 用户完成后自动继续、复检和处理后续步骤，不要求用户手动重复安装、配置或诊断。
8. 只有完成标准全部通过后，才能进入 Step 1。

## 自动执行原则

- 先做后问：工具发现、插件或 MCP 安装、服务器配置、连接发起、浏览器打开、权限检测、诊断和安全重试由 AI 完成。
- 不把命令、配置文件路径、插件搜索、设置页导航或复制粘贴步骤交给用户。
- 平台弹出安装确认或系统权限对话框时，由 AI 发起；用户只负责确认该对话框。
- 登录或 OAuth 页面由 AI 直接打开到可操作状态；用户完成后，AI 自动轮询或重新调用验证工具。
- 自动步骤失败时先读取错误、检查可用工具和日志，并尝试当前环境支持的替代安装或连接路径。只有确认需要本人身份或外部管理员权限时才阻塞。
- 不为验证写入用户业务文件、创建测试 Figma 文件或产生无关外部数据。

## 安装 Skill

- 优先使用当前 Codex 环境的标准 Skill 安装方式。
- 目标目录使用当前环境的 Codex Skill 目录；不硬编码某个用户的绝对路径。
- 安装依赖清单中的全部“包内 Skill”，保留原文件夹名。
- 目标位置存在同名 Skill 时，先比较内容；未经用户确认不覆盖不同版本。
- 安装后验证每个 `SKILL.md` 可读，且 frontmatter `name` 与文件夹名一致。
- 确认 `frontend-design` 及其许可文件已一并安装。
- 确认 `03_视觉/develop-visual-solution/references` 下的视觉预期卡、通用视觉规范、图表选型、结构健壮性检查项均可读。
- 不安装 `ui-ux-pro-max`（已移出流程，原因见依赖清单）。Python 仍需检查，但只作为 Agent Reach 的前置，见下方「Agent Reach」。

## 检查外部能力

### Product Design

Product Design 是 Codex 环境的插件，其他 AI 环境没有。**不要靠判断"我是不是 Codex"来决定要不要调用它——判断身份不可靠，判断能力可靠。** 统一改为能力探测。

**探测（Step 0 做一次，结果写进 Case，之后不再重复纠结）**

- 尝试读取 `product-design:index`。
- **逐个探测三个工作流**：`product-design:ideate`、`product-design:image-to-code`、`product-design:audit`。**每个独立判定、独立降级**——缺一个不影响另外两个。
- 只发现入口或只读取路由说明，不算可用；必须确认具体工作流可调用。

**写入 Case 的标记**

```text
Product Design：ideate 可用 / image-to-code 不可用 / audit 可用
```

**后续行为按标记走**

- **标记为可用的工作流** → **硬门槛**。对应环节每次都必须成功调用；调用失败时停止本次出图并提示 `Product Design 插件未成功调用，请 @Product Design 后让我继续本次出图。`
- **标记为不可用的工作流** → **软门槛**。对应环节跳过，改用 Figma 读写 + Shopee 设计系统正常出图，在 `_自检回执.md` 记一笔"该工作流未参与"。**不阻塞流程，也不反复重试。**
- 三个全部不可用（非 Codex 环境的常态）→ 整个视觉阶段照常运行，Product Design 不参与。
- 标记为可用却调用失败时，明确提示：`Product Design 插件未成功调用，请 @Product Design 后让我继续本次出图。`
- **探测本身必须完成**；探测结果为"不可用"不阻塞流程。未完成探测就开始出图才算违规。

### Figma

- 先发现当前环境中的 Figma 插件、原生连接器或 MCP 读写工具，优先复用已有连接。
- 工具缺失时，自动使用当前环境支持的插件或 MCP 安装能力完成安装与启用；需要平台确认时只让用户批准已弹出的安装对话框。
- 连接未授权时，自动发起 Figma 登录或 OAuth 并打开授权页面；用户只负责登录、同意授权或完成企业审批。
- 授权后自动调用 `whoami` 或等价能力，并确认读取与写入工具同时存在。
- Step 0 尚无 Figma 链接时，不为测试擅自创建文件。已提供节点级链接时，使用安全的最小读取验证目标文件访问权限；编辑权限在开始出稿前确认。
- 失败时自动诊断账号、scope、文件权限、限流和连接状态，并在安全范围内重试；不得直接把安装或配置工作转交给用户。

### Mobbin

- 先发现当前环境中的 Mobbin MCP、插件或等价连接，优先复用已有连接。
- 工具缺失时，自动使用当前环境支持的插件或 MCP 安装与配置能力完成安装、启用和服务器注册；需要平台确认时只让用户批准已弹出的对话框。
- 未授权时，自动发起 Mobbin 登录或 OAuth 并打开授权页面；用户只负责登录、同意授权或完成订阅与企业审批。
- 授权后自动执行最小 screen 搜索和最小 flow 搜索，确认返回有效结果；不把“已安装”或“已登录”当成可使用。
- 失败时自动检查连接状态、授权 scope、订阅权限、地区限制和 MCP 日志，安全重试后再判断是否需要本人或管理员操作。

### Agent Reach

- 确认 `agent-reach` Skill 已安装。
- **先查 Python 前置**：运行 `python3 --version`。Agent Reach 是 Python 包，要求 **≥ 3.10**。
  - macOS 默认不带可用 Python，`/usr/bin/python3` 只是会弹 Xcode 安装框的占位符。
  - 版本不足或没有 Python 时，**这一步 AI 无法代劳**（涉及系统级安装、GUI 弹窗或管理员密码）。按 [`../../02_交互/agent-reach/安装说明.md`](../../02_交互/agent-reach/安装说明.md) 把安装命令给用户，请其执行后回来复检。
- Python 就绪后，从包内离线源安装：`pipx install ./02_交互/agent-reach/runtime`（无 pipx 时用 `python3 -m pip install --user`）。不需要联网拉 GitHub。
- 运行 `agent-reach doctor --json`，至少确认通用搜索与网页阅读能力可用；社交、视频等 channel 按本次研究需要检查，未配置的标注为"未配置"，不阻塞 Step 0。
- **Agent Reach 最终不可用时不阻塞整条流程**：按安装说明的降级路径，改用当前环境可用的联网能力完成调研，并在内部记录"证据来源受限"。不得静默跳过市场调研，也不得编造来源。

### HTML 粗原型

- 确认可创建、打开并检查本地 HTML。
- 如果环境要求用户允许打开本地浏览器，在 Step 0 引导用户完成授权。

## Case 工作区准备

- `04_Case归档模板` 保留在 Design Loop 包内，不在 Step 0 移动、重命名或写入真实 Case 内容。
- Step 0 只验证桌面位置可写；不创建空 Case。
- 用户开始具体需求时，由总流程自动创建桌面 `Design Loop Cases/<Case名称>/` 并复制模板。所有真实 Case 产物写入该目录，源包作为只读流程与设计资源使用。

## 完成标准

### 硬门槛（不满足不得进入 Step 1）

- 依赖清单中的包内 Skill 全部安装且通过基本校验。
- `frontend-design` 完整可读；`references` 下四份视觉材料（视觉预期卡、通用视觉规范、图表选型、结构健壮性检查项）完整可读。
- Product Design 三个工作流**已逐个探测并把结果写进 Case 标记**。探测本身必须完成；**探测结果为"不可用"不算未通过**（非 Codex 环境的正常情况）。
- Figma 账号已授权，读取和写入工具均可用。
- 能读取 `Seller Center Library` 的 `✅ Design Token 设计令牌` 页（node `1:2`）——这是每次出图的强制前置，读不到则整个视觉阶段不可用。
- 本地 HTML 粗原型可打开和检查。
- 桌面可创建独立 Case 根目录，且真实 Case 不写入 Design Loop 源包。

### 软门槛（不满足可继续，但必须先问用户并记录标记）

Mobbin 与 Agent Reach 是市场调研的两个证据来源。Step 0 尽力连接，**但连不上时不能自己往下走**——因为 Step 2 有三处完成标准硬性要求"每个方向映射真实研究机制与来源"，没有证据来源就永远满足不了，会死循环。

**处理方式：**

1. 两个都连上 → 写标记 `市场证据来源：已连接（Mobbin ✓ / Agent Reach ✓）`，Step 2 的研究映射约束**照常全部生效**。
2. 有一个连不上 → 用另一个继续，写标记记录哪个缺，并在研究结论中标注证据覆盖不足。
3. **两个都连不上 → 必须问用户一次**：
   ```
   Mobbin 与 Agent Reach 均未连接，本次将没有外部市场证据，三个方案方向会改为从现有页面和 Step 1 痛点反推。确认这样继续吗？
   ```
   - 用户确认 → 写标记 `市场证据来源：用户确认无证据`，Step 2 下游约束按标记切换（见 `research-market-solutions`、`explore-interaction-directions`、`build-rough-prototypes` 的对应条款）。
   - 用户不确认 → 停在 Step 0，按 [`../../02_交互/agent-reach/安装说明.md`](../../02_交互/agent-reach/安装说明.md) 协助装好再继续。

**不得在用户未确认的情况下自行降级，也不得因为工具缺失就编造来源。** 其他非本次所需 channel 可标注为未配置，不触发上述询问。

### 收尾

- 所有需要用户完成的操作已完成并重新验证。
- 向用户明确说明：哪些是已就绪的、哪些走了降级路径、哪些还需要用户自己装（Python、Product Design 插件、Mobbin 订阅）。

硬门槛未达到时，继续 Step 0，不声称安装完成。软门槛未达到时可以进入 Step 1，但不得把降级说成就绪。

## 输出

默认只输出两类结果，并附一句下一步引导：

- `Design Loop 已就绪。下一步：请用一句话说明需求；修改现有页面时同时提供节点级 Figma 链接。`
- `需要用户操作：已为你打开…。请只完成…。完成后我会自动复检；仅当页面无法自动回传时再告诉我“继续检查”。`

不得把可由 AI 完成的安装、配置、打开页面或诊断步骤写入“需要用户操作”。
