# 自动连接 Figma 与 Mobbin

本文件定义 Step 0 的强制自动连接与恢复顺序。目标是让用户只处理本人身份、授权或企业权限，其他工作由 AI 完成。

## 通用顺序

对 Figma 和 Mobbin 分别执行以下闭环，不得因为发现插件名称或历史配置就跳过验证：

1. 枚举当前环境可调用的插件、连接器、MCP、工具搜索和安装能力。
2. 优先复用已存在的官方或当前环境原生连接；存在多个同类连接时，优先选择同时覆盖本流程所需读写或搜索能力的连接。
3. 工具缺失时，自动调用当前环境提供的插件安装、连接器安装或 MCP 注册能力；自动完成无需身份的配置。
4. 连接未授权时，自动发起登录或 OAuth，并直接打开授权页面或系统弹窗。
5. 只在页面已打开且确实需要本人时请求一个用户动作，例如登录、同意 OAuth、输入验证码、批准文件访问或请求企业管理员审批。
6. 用户完成后自动继续：重新发现工具、读取连接状态、执行最小验证。不得要求用户重新输入需求、重复打开页面或手动运行命令。
7. 验证失败时读取原始错误和可用日志，依次检查安装状态、服务器进程或连接、授权 scope、账号或订阅、目标资源权限、地区限制和限流；在安全范围内修复并重试。
8. 只有用尽当前环境可执行的安装、配置、连接和安全重试路径，并确认剩余动作必须依赖本人身份或管理员权限时，才输出阻塞。

## Figma 验证闭环

1. 确认存在账号检测能力，以及至少一种读取工具和一种写入工具。
2. 调用 `whoami` 或等价能力验证真实登录态；仅发现工具不算连接成功。
3. 无目标链接时不创建测试文件。记录账号和可用读写工具即可。
4. 有节点级 Figma 链接时，解析 file key 与 node id，执行最小只读访问；不要扩大读取范围。
5. 开始出稿前，确认目标文件可写；可通过现有权限信息或对目标文件的非破坏性写入能力检查完成，不新建无关文件。
6. 账号有效但目标文件不可访问时，自动打开正确文件或权限页面；只请用户批准文件访问、切换正确账号或完成企业审批。

完成标准：账号已认证，读取与写入工具均可调用；提供目标链接时，目标文件可读取，并在出稿前确认可写。

## Mobbin 验证闭环

1. 确认存在可搜索 screen 的能力和可搜索 flow 的能力；只具备普通网页浏览不等价于 Mobbin 连接。
2. 缺少工具时，自动使用当前环境支持的插件或 MCP 安装和注册能力；优先使用官方或已受信任的连接。
3. 未认证时自动发起登录或 OAuth，并打开 Mobbin 的授权页面；只请用户完成登录、OAuth 同意、订阅确认或企业审批。
4. 授权后分别运行一次范围最小的 screen 查询和 flow 查询，确认返回可读取的真实结果。
5. 空结果不直接判定成功：更换一个常见产品或通用界面关键词复检，排除查询本身无结果。
6. 若报错，自动检查 MCP 连接、登录态、scope、订阅等级、地区限制、速率限制和服务状态，再安全重试。

完成标准：screen 与 flow 搜索都返回有效结果，且后续 Step 2 可直接复用该连接。

## 用户可见阻塞格式

只描述已打开的页面和唯一需要本人完成的动作：

`需要用户操作：已为你打开 <Figma/Mobbin> 的 <登录/授权/权限> 页面。请只完成 <一个动作>；完成后我会自动复检，仅当页面无法自动回传时再告诉我“继续检查”。`

不得输出插件搜索、安装命令、MCP 配置、日志排查或设置页导航步骤让用户手动执行。
